# Git Prep

Этот документ нужен для безопасной подготовки проекта к публикации в Git.

## Что нужно отправлять в Git

- `.py` файлы
- `README.md`
- `docs/`
- `tests/`
- `pyproject.toml`
- `requirements.txt`
- `.gitignore`

## Что нельзя отправлять в Git

- реальные Excel/CSV/RTF с бизнес-данными
- результаты расчетов
- сохраненные модели
- архивные старые файлы
- локальные логи
- виртуальное окружение
- локальные настройки IDE

## Что уже закрывает `.gitignore`

Сейчас `.gitignore` исключает:

- `data/to_process/`
- `data/training/`
- `data/reference/`
- `data/results/`
- `archive/`
- `artifacts/`
- `venv/`
- `.idea/`
- логи
- типовые табличные и нормативные файлы

## Что проверить перед первой загрузкой в Git

1. Убедиться, что в корне нет Excel/CSV/RTF-файлов
2. Убедиться, что реальные данные лежат только в `data/`
3. Убедиться, что старые результаты лежат только в `archive/`
4. Убедиться, что код запускается через `inspect-data`
5. Убедиться, что README и docs актуальны

## Базовый порядок действий для первой публикации

Когда будете готовы, порядок обычно такой:

```bash
git init
git add .
git status
git commit -m "Initial cleaned version of OKPD classification project"
```

Перед `git commit` обязательно смотрите `git status`.

Если там внезапно видны реальные данные, значит надо остановиться и поправить `.gitignore`.

## Практическое правило

Если файл содержит:

- реальные номенклатурные данные
- реальные ставки
- реальные внутренние справочники
- реальные результаты обработки

его не нужно публиковать.
