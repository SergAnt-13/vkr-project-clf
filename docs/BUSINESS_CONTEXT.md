# Business Context

Этот документ описывает проект как прикладную систему, а не как набор Python-скриптов.

## Задача

Есть массив номенклатурных позиций.

Для части позиций код ОКПД2 уже указан, для части — нет, а для части он может быть недостоверным или неоднородным.

Нужно:

- автоматически предсказывать код ОКПД2
- получать итоговую ставку НДС
- сравнивать разные подходы по качеству
- подготовить основу для дипломной демонстрации и дальнейшего развития

## Бизнесовый смысл

Система помогает сократить ручную работу по классификации номенклатуры и дает воспроизводимый механизм получения предположений по ОКПД2 и НДС.

Это не “истина в последней инстанции”, а инструмент поддержки принятия решения и ускорения обработки.

## Что является объектом анализа

Основной объект анализа — строка номенклатуры, то есть товарная позиция с текстовым названием и, желательно, дополнительными атрибутами.

На практике сейчас главным сигналом для модели является текст названия товара.

## Какие управленческие вопросы проект позволяет закрывать

- можно ли автоматически восстановить код для неразмеченных позиций
- насколько полезны текущие коды из основной выгрузки как обучающая база
- улучшается ли результат при переходе к более качественной, но меньшей обучающей выборке
- дает ли BERT заметное преимущество относительно baseline

## Что именно сравнивается в дипломной логике

Сейчас в проекте естественным образом заложено сравнение двух классов подходов:

- классический текстовый ML-подход
- трансформерный deep learning подход

То есть у вас уже есть естественный каркас для сравнительного анализа.

## Что является ограничением

- если обучающая выборка шумная, модель учится на шуме
- если обучающая выборка неразнообразна, модель плохо переносится на новые типы товаров
- если эталон размечен частично, результат придется оценивать аккуратно

## Почему новый почти корректный размеченный файл важен

Если у вас есть `1500-2000` почти правильных строк, это может быть значительно ценнее, чем десятки тысяч строк с сомнительным качеством меток.

Для диплома это важно потому, что вы сможете аргументированно обсуждать:

- влияние качества разметки
- влияние объема выборки
- влияние разнообразия классов

## Что считать успешным состоянием проекта

Проект можно считать приведенным в рабочий дипломный вид, если:

- структура файлов понятна
- код запускается воспроизводимо
- входы и выходы документированы
- обучающий файл можно заменить без переписывания проекта
- результаты baseline и BERT можно сравнить на одном и том же наборе
- Git-репозиторий не содержит конфиденциальные выгрузки
